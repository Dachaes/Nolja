# NOLLJA 오셀로 개발 안내

## 실행

Node.js 24와 Java 21 기준입니다. **백엔드와 프런트엔드를 함께 실행해야 합니다.**

터미널 1, Git Bash:

```bash
cd backend
export JAVA_HOME=../.tools/jdk-21.0.13.0.2+1
export PATH="$JAVA_HOME/bin:$PATH"
./mvnw spring-boot:run
```

터미널 2:

```powershell
cd frontend
npm.cmd install
npm.cmd run dev
```

Windows에서 `npm.ps1` 실행 정책 오류가 발생하면 `npm.cmd`를 사용하세요. PowerShell에서 백엔드를 실행하는 명령은 `../backend/README.md`를 참고하세요.

연결 복구 기능은 새로운 방 상태 필드를 사용하므로 변경 사항을 적용한 뒤 백엔드와 프런트엔드를 함께 재시작하세요.

## 두 기기로 플레이

1. 두 기기를 같은 Wi-Fi에 연결합니다.
2. PC와 상대 기기 모두 Vite가 출력하는 **Network 주소**(예: `http://192.168.0.10:5173`)로 접속합니다. `localhost`는 다른 기기에서 PC를 가리키지 않습니다.
3. 닉네임을 입력하고 `방 만들기`를 누릅니다. 방장은 흑입니다.
4. 대기실의 `초대 링크 복사`로 친구에게 `/room/방코드` 주소를 보냅니다.
5. 친구가 링크에서 다른 닉네임을 입력하고 입장하면 백으로 배정됩니다.
6. 각자는 자신의 차례에 자신의 돌만 둘 수 있습니다. 착수는 서버가 검증하고, 입장·착수·종료 상태는 WebSocket으로 두 기기에 즉시 전달합니다.

같은 PC에서 점검할 때는 일반 브라우저와 시크릿 창 등 독립된 브라우저 세션을 사용하세요. 탭 복제는 브라우저에 따라 참가 정보를 함께 복사할 수 있습니다.

휴대폰에서 접속되지 않으면 PC 방화벽의 개발 서버 포트 허용 여부를 확인하세요. 다른 네트워크의 친구와 플레이하려면 서버와 프런트엔드를 배포해야 합니다. 배포 시 `/api`와 `/ws` 역방향 프록시, `/room/*`의 SPA fallback을 설정합니다. `/ws`는 WebSocket 업그레이드와 원래 Host 전달이 필요합니다.

일반 HTTP 환경에서 자동 복사가 지원되지 않으면 선택해서 복사할 수 있는 링크 입력란을 표시합니다.

## 현재 동작

- 닉네임 2~12자, 문자·숫자·`_`·`-` 허용. 같은 방에서는 중복 이름을 거절합니다.
- 2인 비공개 방 생성, 링크 입장, 대기실, 방 코드 표시, 상대 입장 후 보드 전환.
- 본인 참가자에 `(나)` 표시, 내 차례/상대 차례 표시, 상대 차례에는 착수 불가.
- 빈칸 포함 조기 종료, 자동 패스, 8방향 뒤집기, 승패·무승부 판정.
- 종료 시 본인 기준 승리·패배·무승부와 참가자별 최종 점수, 마지막 보드를 표시합니다.
- 같은 방에서 재대결 요청·취소·수락이 가능하며 두 사람이 동의하면 흑백을 교대해 새 판을 시작합니다.
- 결과 화면의 로비 복귀는 방을 닫고 본인의 참가 정보·캐시를 정리합니다. 닉네임은 다음 방 만들기에 그대로 사용할 수 있습니다.
- 명시적인 방 나가기는 방을 닫고 상대에게 종료 안내를 표시합니다.
- 인증한 WebSocket 연결에서 최초 상태와 이후 변경을 받습니다. 정상 대국 중에는 `/state`를 주기적으로 조회하지 않습니다.
- 같은 탭에서 새로고침하면 마지막 확인된 보드를 먼저 읽기 전용으로 보여주고, 기존 참가 토큰으로 인증한 뒤 최신 상태를 받습니다.
- 한 사람의 연결이 끊기면 양쪽 착수를 막고 2분 동안 복귀를 기다립니다. 상대의 연결 상태와 남은 시간을 표시합니다.
- 네트워크가 돌아오면 자동으로 재접속합니다. 복귀 기한이 지나면 방을 종료하고 마지막 보드를 표시하며, 단절을 승패로 판정하지 않습니다.
- 로비에서 `이전 방으로 돌아가기`로 같은 탭의 참가 중인 방에 복귀할 수 있습니다. 명시적으로 퇴장하면 복구 정보도 제거합니다.
- 늦게 도착한 HTTP 응답이나 중복 소켓 메시지가 보드를 과거 상태로 되돌리지 않도록 `revision`을 비교합니다.
- 서버 메모리 저장이며 생성 후 6시간 유효합니다. 서버 재시작 시 방이 사라집니다.
- 회원 로그인·전적과 기권 판정은 아직 구현하지 않았습니다.

규칙은 [세계오셀로연맹 공식 규칙](https://worldothello.org/about/about-othello/othello-rules/official-rules/english)을 따르며 점수는 보드에 놓인 실제 돌 개수입니다.

## 구조

```text
src/features/
  room/
    api/             # HTTP 요청과 API 오류
    model/           # 닉네임 검증, 탭별 참가 정보, URL 이동, revision 기반 캐시 병합
    realtime/        # 소켓 메시지 검증, 연결·인증·heartbeat·재접속
    recovery/        # 읽기 전용 보드 저장/복원, 접속 안내, 복귀 카운트다운, 이전 방 복귀
    hooks/           # 실시간 연결과 React Query 연동, 착수 mutation
    lobby/           # 서버 퇴장, 참가 정보·캐시 정리, 로비 이동
    rematch/         # 재대결 요청 훅, 동의·취소·수락 화면
    components/      # 닉네임 폼, 입장 화면, 헤더, 대기실, 초대 링크, 연결 상태
    RoomRouter.tsx   # /와 /room/:code 라우팅
    RoomPage.tsx     # 입장, 대기, 대국, 오류 상태 조합
  othello/
    components/      # 보드, 칸, 돌, 참가자, 점수, 규칙 안내
    result/          # 본인 기준 결과 계산과 최종 점수 카드
    rules.ts         # 프런트엔드 착수 힌트와 점수 계산
    types.ts         # 보드와 참가자 타입
    OthelloGame.tsx   # 서버에서 받은 상태로 보드 표시
```

스타일은 모두 `*.module.scss`로 유지합니다. 색상 토큰은 `src/styles/global.module.scss`, 색상표는 루트 `color.md`에 있습니다. 백엔드는 `room`과 `othello` 패키지로 나뉩니다.

`playerId`는 서버가 발급한 참가자 ID, `nickname`은 화면 표시 이름, `userId`는 비회원일 때 `null`입니다. 권한 검증은 별도의 무작위 참가 토큰을 사용하며 초대 링크에는 토큰을 넣지 않습니다.

## 실시간 상태 흐름

1. 입장 응답의 참가 토큰을 저장하고 `/ws/rooms/{code}`에 연결합니다.
2. 첫 메시지로 토큰을 인증하면 서버가 현재 방 상태 전체를 보냅니다.
3. 착수는 기존 HTTP API로 요청합니다. 서버가 참가 권한·차례·좌표·버전을 검증합니다.
4. 검증한 결과를 같은 방의 소켓에 전송하고, 각 화면은 최신 `revision`만 캐시에 반영합니다.
5. 연결이 끊기면 1초부터 최대 10초 간격으로 재시도합니다. 재연결 시에도 전체 상태를 받아 누락된 변경을 보완합니다.

`connectRoom.ts`는 전송 수명만, `useRoomConnection.ts`는 React와 캐시 연동만 담당합니다. `useRoom.ts`는 착수를, `useRematch.ts`는 재대결 요청을, `useReturnToLobby.ts`는 퇴장과 로컬 정리를 담당합니다. 착수·재대결 요청 실패 시에는 `/state`를 한 번 조회해 서버 처리 여부를 확인합니다. heartbeat는 15초마다 보내며 수신이 45초를 넘겨 끊긴 경우 다음 확인 시 재연결합니다.

## 결과 · 로비 · 재대결

1. 두 사람 모두 둘 곳이 없어지면 최종 점수와 본인 기준 결과가 나타납니다. 빈칸은 점수에 더하지 않습니다.
2. `재대결 요청`을 누르면 상대의 응답을 기다립니다. 기다리는 동안 `요청 취소`로 동의를 철회할 수 있습니다.
3. 상대가 `재대결 수락`을 누르면 같은 방·참가 ID·토큰을 유지하고 흑백을 바꿉니다. 보드·점수·마지막 수·패스 상태는 새 판으로 초기화합니다.
4. `로비로 돌아가기`를 누르면 기존 방을 닫고 `/`의 방 생성 화면으로 이동합니다. 남은 사람에게는 최종 결과와 상대 복귀 안내를 보여줍니다. 닫힌 방에서는 재대결할 수 없습니다.

`gameNumber`는 판이 바뀔 때만, `revision`은 동의·취소·착수·접속 상태가 바뀔 때마다 증가합니다. 재대결 입력은 `{ gameNumber, ready }`이며 서버가 토큰으로 동의한 사람을 결정합니다. 두 기기가 동시에 동의해도 한 번만 시작하고, 지난 판의 지연 요청은 다음 판에 적용되지 않습니다. 재대결 시작에는 두 사람의 연결도 필요합니다.

방이 닫힌 뒤에도 참가 토큰이 남아 있는 사람은 같은 탭 새로고침으로 최종 보드와 종료 이유를 복구할 수 있습니다. 방의 6시간 유효 시간이 지나거나 서버를 재시작하면 서버 데이터가 사라집니다. 회원 전적 저장은 후속 단계입니다.

## 새로고침 · 연결 끊김 복구

1. `sessionStorage`에 탭별 참가 정보와 서버에서 확인한 보드를 저장합니다. 복구용 보드에는 비밀 토큰을 넣지 않습니다.
2. 새로고침 직후에는 저장된 보드를 표시하되 착수·재대결을 비활성화합니다. 인증된 소켓에서 전체 상태를 받은 뒤에만 입력을 엽니다.
3. 저장소 데이터와 서버 상태 캐시를 분리합니다. 저장소의 큰 버전 값이 손상되었더라도 정상 서버 상태를 막지 못합니다.
4. 인터넷이 끊기면 즉시 입력을 막습니다. 다시 온라인이 되거나 절전에서 화면으로 복귀하면 재연결을 시도합니다. `pagehide`/`pageshow`도 처리해 브라우저 뒤로/앞으로 캐시에 남은 소켓을 정리합니다.
5. 서버는 마지막 소켓이 닫히거나 heartbeat가 45초 동안 오지 않으면 단절로 판단합니다. **단절 확인 시점부터 2분** 동안 같은 참가 ID와 토큰으로 복귀할 수 있습니다.
6. 대기 중에는 양쪽 착수와 새로운 재대결 동의를 막습니다. 복귀하면 보드·색상·차례·점수·재대결 동의를 유지합니다. 유예 기한이 지나면 서버가 방을 닫습니다.

같은 참가자의 새 소켓이 먼저 열리고 이전 소켓이 늦게 닫혀도 연결 중으로 유지합니다. 카운트다운은 서버 시각 차이를 보정한 안내이며 종료 결정은 서버에서 합니다. 인증 실패·없는 방·만료 오류를 받으면 저장된 참가 정보와 보드를 정리합니다.

저장소가 차단되면 현재 화면의 대국은 가능하지만 새로고침 후 참가 정보 복구는 보장할 수 없습니다. 앱 파일을 내려받을 수 없는 완전한 오프라인 새로고침은 지원하지 않습니다. 서버 재시작 복구와 영구 전적 저장은 별도 저장소가 필요합니다.

## 검증

```powershell
npm.cmd test
npm.cmd run build
# 백엔드를 실행한 상태에서:
npm.cmd run test:e2e
```

E2E 테스트는 Windows에서 설치된 Edge를 사용합니다. 다른 운영체제에서는 `npx playwright install chromium`으로 테스트 브라우저를 준비하세요. 독립된 데스크톱/모바일 브라우저에서 초대, 입장, 착수, 새로고침, 퇴장, 잘못된 링크, 소켓 단절 중 착수 제한과 재연결을 검증합니다. 정상 대국과 재접속에서 `/state` 요청이 없는지도 확인합니다.

결과 테스트는 합법 수로 두 판을 진행해 각자의 승패·점수, 재대결 요청·취소·수락, 흑백 교대, 로비 복귀 실패 후 재시도, 상대 결과 유지와 참가 토큰 정리를 확인합니다.

복구 테스트는 소켓 단절 중 새로고침, 읽기 전용 보드, 손상된 저장 버전, 네트워크 복귀, 상대 입력 차단, 이전 방 복귀, 무효 토큰 정리, 닫힌 방 결과의 새로고침 복구를 확인합니다.

다른 포트의 테스트 서버를 쓰려면 백엔드를 해당 포트로 실행한 뒤 아래처럼 지정할 수 있습니다. 기본 포트는 백엔드 8080, 프런트엔드 5173입니다.

```powershell
$env:NOLLJA_API_TARGET = 'http://127.0.0.1:18080'
$env:NOLLJA_E2E_BASE_URL = 'http://127.0.0.1:15173'
npm.cmd run test:e2e
```
