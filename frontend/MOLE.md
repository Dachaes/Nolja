# 두더지잡기

메인페이지에서 두더지잡기를 선택하고 닉네임으로 방을 만듭니다. 초대 링크로 친구가 들어와 두 사람이 연결되면 3초 카운트다운 뒤 시작합니다. 기존 오셀로와 같은 백엔드, 방 코드, 참가 토큰, WebSocket 연결을 사용합니다.

## 규칙

- 4×4 구멍에서 30초 동안 겨룹니다. 처음에는 최대 3마리, 후반에는 최대 4마리가 동시에 등장하고 점점 빨라집니다.
- 같은 두더지는 서버에 먼저 도착한 유효한 요청 한 번만 득점합니다. 한 마리의 기본 점수는 100점입니다.
- 연속 3회마다 한 마리당 보너스가 25점씩 늘어납니다. 3~5콤보는 125점, 6~8콤보는 150점이며 최대 200점입니다.
- 빈 구멍을 누르면 콤보가 끊깁니다. 이미 잡혔거나 숨은 두더지에 대한 늦은 요청은 점수와 콤보를 바꾸지 않습니다. 놓친 두더지는 콤보를 끊지 않습니다.
- 연결이 끊기면 서버가 남은 시간과 두더지의 시간을 멈춥니다. 기존 복귀 유예 시간 안에 두 사람이 연결되면 이어집니다. 명시적으로 방을 나가면 승패 없이 종료합니다.
- 제한 시간이 끝나면 점수로 승패/무승부를 표시합니다. 두 사람이 재대결에 동의하면 점수와 콤보를 초기화합니다.

## API

`POST /api/rooms`에 `{ "nickname": "민서", "gameType": "whack-a-mole" }`를 보냅니다. `gameType`을 생략하면 기존 오셀로 방을 만듭니다. 공개 초대 정보와 방 상태에 `gameType`이 포함됩니다.

두더지 방의 `mole`에는 `startsAt`, `endsAt`, `pausedAt`, `finished`, 16개 `holes`, 참가자별 `scores`가 포함됩니다. 구멍은 비어 있으면 `null`, 두더지가 있으면 고유 `id`와 등장/만료 시각, 잡은 사람 `claimedBy`, 획득 점수 `points`를 가집니다.

인증된 참가자는 `POST /api/rooms/{code}/hits`에 `{ "hole": 0, "moleId": 1, "gameNumber": 1 }`를 보냅니다. 구멍 번호는 0~15이고 빈 구멍은 `moleId: null`입니다. 참가 토큰은 기존과 같이 Authorization Bearer 헤더로 전달합니다. 점수·콤보·시간은 클라이언트에서 받지 않고 서버가 결정합니다. 다른 구멍을 동시에 누른 요청을 막지 않도록 방 revision 대신 두더지 ID와 게임 번호를 검증합니다.

서버 타이머가 변경된 상태를 기존 소켓으로 전달하므로 게임 상태 폴링은 필요하지 않습니다. 재대결·퇴장은 기존 방 API를 사용합니다. 서버 재시작 시 방이 사라지는 기존 단일 서버 메모리 구조를 따릅니다.

## 실행 및 검증

기존 개발 명령으로 프런트와 백엔드를 실행합니다. 변경 사항을 적용하려면 백엔드도 재시작해야 합니다. 배포 시에는 프런트와 백엔드를 모두 갱신합니다.

- 프런트: `npm run build`, `npm test`
- 서버: Java 25에서 `./mvnw -B -ntp test` (Windows는 `mvnw.cmd`)
- 실제 두 기기 흐름: 백엔드를 실행한 뒤 `npm run test:e2e -- tests/e2e/mole.spec.ts`

브라우저 테스트는 방 생성/초대, 동시 잡기, 마우스·모바일 터치, 점수 동기화, 연결 복구, 새로고침, 30초 종료, 재대결, 퇴장을 검증합니다. 별도 포트 검증에는 프런트의 `NOLJA_API_TARGET`과 테스트의 `NOLJA_E2E_BASE_URL`을 지정합니다.
